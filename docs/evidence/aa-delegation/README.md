# 共享单聊中的 AgentAssistant 委托

在 `5d5421c1e5e0` 基线上，原生 AgentAssistant 可以启动委托并生成报告。子模型仍在运行时，原共享 Work 已显示完成，重新查询该 Work 得不到委托 ID。本批在隔离 ToolBox 通过插件发现加载 AgentAssistant，分别核对了共享发送、原生插件、子模型请求和归档回执。

| 用户动作 | 实测结果 |
|---|---|
| 子任务运行时退出桌面，重开原 Profile | 父 Work 和原生委托 ID 相同。发送及启动各一次 |
| 在发起桌面停止委托 | 原生宿主先接受取消，等当前轮结束再确认取消。重复停止没有启动新任务。只读 PWA 观察到原委托状态变化，执行写请求为 0 |
| 等待自然完成 | 子任务实际经历两轮模型请求，只有一次委托启动。桌面和 PWA 均可打开绑定到原 Work 的报告 |
| 在子模型请求已发出、尚未返回时强停 ToolBox | 已接纳的 Work 保留待核查，子任务保留原 ID 和 unknown。重启、重交原请求均未增发模型请求或写入助手终稿；同一后端能读回此前另一条已完成任务的相同报告哈希 |
| 普通本机委托 | 走本机单聊入口发起的两次委托分别正常完成和取消，各启动一次，共享 Work、共享子任务与共享工具调用记录均为 0 |

## 执行归属

AgentAssistant 创建委托 ID、运行原生 Flowlock 循环、响应停止并归档结果。Work 在启动子模型前登记原生工具调用与委托身份，每一轮请求都使用该 Work 的执行权限。查询报告时核对任务、工具调用、委托 Agent 和归档哈希。重开的桌面可按原身份发出停止请求。原生管理员保有宿主既有的管理能力。[宿主差异](host.patch)

恢复有两种不同的依据。已经派发的子模型请求如果缺乏结果，原任务进入待核查。父回复已经持久保存、子模型也已结算时，系统可以从原生归档核对同一任务，再发布原父回复。两条回归用例分别覆盖子任务投影缺失，以及投影已经提交、父 Work 的完成标记丢失，均核对原模型请求一次、Journal 两行。

## 验证环境

Linux x64、Node 24、带沙箱的 Electron、独立浏览器 Profile 和本地合成 Provider。真实插件只在测试实例显式启用。PWA 验证使用移动视口 Chromium。执行中断用强停 ToolBox 进程验证，未模拟整机断电。

普通本机回归可以在仓库根运行 `node tests/aa-delegation/local.cjs`。共享委托与桌面用例的启动参数见上方两份分项记录。

本批原生宿主测试 201/201，协作测试 53/53，桌面可信 IPC 调用方测试 3/3。
