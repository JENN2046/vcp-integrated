## 实际请求

从隔离 Electron 的发送按钮发起普通本机单聊。合成 Provider 先发出可见前缀和工具请求，再保持下一轮连接打开。真实 ToolBox 运行普通计数工具，桌面在工具回执处按上下文预算自动请求中断。基线在默认关闭角色分隔时漏掉这处边界，开启分隔时又将实际中断的部分回复记成了 `completed`。[两组基线与候选回执、截图和重跑命令](desktop/README.md)

修复后，ToolBox 在**原 SSE 响应**上发送 `interrupted` 和结束标记。桌面按当前本机入场租约把前缀写入原消息 ID。自动压缩请求进入代理时，物理 History 已有这条记录；合成压缩模型收到其正文。两种角色分隔设置各生成一个检查点，一条新回复使用该检查点并正常完成。重开同一 Profile 后四条 History 与关闭前逐条相同，每组工具执行一次，共享 Work 和 Journal 行数为零。

本机持久化另测了原 ID 幂等重提、冲突终态、错误或失效租约、普通完成，以及重启时只有中断记录的情形。仅存中断记录的未结租约仍须核对，恢复过程不会擅自派发。[本机入场回归](../../../tests/native/topic-admission-interrupted-terminal.test.cjs)

JSON 中的 `revision` 是实测时的基线 HEAD。候选在提交前运行，`loaded` 列出实际代码 SHA-256。可用本批提交中的同路径文件核对。开启及关闭角色分隔的候选各核对了 17 份源码，两个基线各核对了 11 份，均与对应的源码匹配。
