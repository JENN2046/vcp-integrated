# NativeSync 三个剩余规则入口的归属复审

从集成提交 `4f3f9063db7b` 继续。对每项先记录实际执行者和有区分力的输入，再对照桌面、ToolBox 及共享 worker。测试使用 Linux 沙箱 Electron、真实 ToolBox、合成资料与回环 Provider。

| 规则 | 已证实的重复裁决 | 归属与复验 |
|---|---|---|
| requestMetadata | 普通单聊组装与 worker 分别判断同一组 History 的时间戳能否附入消息，各执行四次。 | 两端改用 VCPChat 的原生 ESM 函数。四条绑定的 ID、角色、时间戳、索引与正文哈希正确；同路径 Handler 和 Provider 请求前后归一比较一致。桌面群聊对非有限时间戳的判断不同，保留其语义。[完整请求与反例](metadata/README.md) |
| modelSelection | 普通桌面群聊、共享构包与冻结模型检查分别选择统一模型或发言成员模型；带首尾空白的合法配置实际触发 409。图片准入也对同一获准模型产生误拒。 | 共用原生选择函数。两成员的实际派发、空模型拒绝与 Work 重放均实测。PNG 另外经上传、ready 和准入核对；名单外模型仍被拒绝。[模型与图片准入回执](model/README.md) |
| streamDelta | 普通群聊、邀请群聊和 worker 都从解码后的同一帧选取可见正文；多字段有值时按相同优先级取一个。 | 共用一个文本提取函数。改后普通、邀请、worker 分别实测 14、7、14 帧；持久回复前后一致。另有 16 个普通共享单聊终稿恢复案例覆盖封存、断流和重放。[逐帧与终态回执](stream/README.md) |

三处旧插件入口均保留为转发。此前清单中的 16 个入口现为 13 个 CommonJS 转发、2 个 ESM 转发和 1 个向共享实现传入宿主依赖的适配器。本结论覆盖 `nativeRules` 目录；各宿主继续负责各自的协议边界、权限和执行终态。

最终组合回归使用 Node 24。原生套件通过 257 项，6 项因缺少历史压缩夹具而跳过；协作套件 60 项全过。协作回归初跑时，测试用裸读取正好撞上后台对同一 History 的原子替换，出现 `HISTORY_IDENTITY_CHANGED`。观察端测试已改为通过宿主原有的 `readSerialized` 读同一队列，原有 History 内容、顺序和次数断言保留。使用现有空知识库 watcher 夹具处理本机 inotify 配额限制。未部署到日用端。
