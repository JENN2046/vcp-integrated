# 普通共享群聊与 AA 的收尾

复审的反例来自没有取消剩余接力的一轮 A、B、C 群聊，最后一位成员 C 在回复中发起一次原生 AgentAssistant 委托。本批对照两种结束顺序，并用复审时留下的两份合成数据库验证升级。实测使用隔离的真实 ToolBox、Chrome PWA 和回环合成 Provider。

| 结束顺序 | 复审基线 | 本次结果 |
|---|---|---|
| AA 先结束，C 后提交 | 中央准入为 completed，移动执行却为 review_required | 三位成员各提交一次，中央与移动执行均为 completed，同话题下一轮 A、B、C 正常完成。[改前](../stage-review/uncut-early.json) · [改后](live/early.json) |
| C 先提交，AA 仍运行 | 三条回复已提交，Work 进入 blocked_config；AA 随后正常完成仍未释放话题 | 移动执行为 recovering，中央准入保持 dispatched。PWA 显示「成员回复已保存，等待原生任务结束」，没有人工解除入口。此时提交下一轮得到 SHARED_TOPIC_BUSY；AA 的原生回执到达后两本账自动完成，下一轮可以发送。[改前](../stage-review/uncut.json) · [改后](live/late.json) |

**改动。** 普通群聊与取消后续成员共用结算事务。成员计划只包含非负序号的发言步骤；AA 子请求与工具调用按各自的回执核对。在同一数据库事务内确认成员身份与回复、Journal 对应记录和原生任务终态，再更新中央准入和移动执行。等待状态由既有原生结算事件唤醒，不需要新的调度器。旧中央 finish 回执命中时也重新核对事实。旧库自动修复针对全部成员都已提交且符合复审故障特征的记录。明确的人工放弃、未知子请求、未结算工具或缺失原回复继续按原语义处理。[宿主差异](host.patch)

**旧库验证。** 取复审原库的一致备份，连同原 AA 报告和原生工具记录放入隔离实例。先启动旧代码复现故障，再替换程序，沿用同一个隔离数据库文件。两条历史 Work 均恢复为 completed，原 Work、请求、成员回复、AA 与工具调用 ID、History 和 Journal 内容逐项一致。重开可读取原报告，哈希与历史回执一致。从升级启动到显式发起新一轮，模型和工具调用均新增 **0 次**。两份库随后各自成功接纳并完成一轮新群聊。[备份方法及复跑](upgrade/README.md) · [早到旧库](upgrade/early.json) · [晚到旧库](upgrade/late.json)

**回归。** 原生宿主测试 218/218，协作测试 53/53。专项用例覆盖 AA 子工具仍在派发时保留最后一条成员回复的持久写入意图，收到终态回执后只提交该原回复一次；也覆盖成员计划不一致、缺少 Journal 行、AA 终态证据不全、人工放弃及后继 Work 已占用话题。[实时用例与复跑](live/README.md) · [安全边界用例](../../../tests/native/group-settlement-safety.test.cjs)
