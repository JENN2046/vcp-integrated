# 桌面在中央恢复后读回已选话题

基线为 5f811d0ca0d2。两轮均用隔离 Linux Electron、空白历史投影、同一份合成桌面绑定，以及 R4 的 final-schema4-cold.sqlite 冷备份副本（SHA-256 ac62c2892794656892e9d523fe898717be192fe599768a0730a86eef4e4caae7）。先在中央停止时选择原故障群话题并输入草稿，再从原地址启动 ToolBox。恢复期间只观察窗口，没有重新选择、点击刷新或重新启动桌面。

| 观察时点 | 桌面与中央 |
| --- | --- |
| 改前 | 中央已就绪 30 秒后，原窗口仍显示 NETWORK_UNAVAILABLE。共享运行时的首次接入失败后返回了永久降级对象。[截图](baseline-after-restore.png) |
| 改后，中央离线 | 原窗口暂时显示加载失败，输入框保留 RECOVERY_DRAFT。[截图](fixed-offline.png) |
| 改后，中央恢复 | 同一个 Electron 进程、同一个话题，自动显示用户输入及 A、B、C 的三条正式回复。错误提示已移除，草稿仍在。[截图](fixed-after-restore.png) |
| 再次停启中央 | 同一窗口全程保留四条已加载消息和草稿。中央从刚停止的数据库副本恢复。 |

[桌面回执](desktop.json) 包含 PID、话题、草稿、可见消息 ID、正文与观测时间。[中央回执](central.json) 对比原备份和三次运行的准入、原生请求、接力状态、步骤和 Journal。恢复后桌面的本地 History 与中央四条正式记录的 ID、角色和正文逐项相同。原 Work 为 completed，三次运行的合成 Provider 均收到零次请求。[实际加载代码哈希](loaded.json)

修复复用原共享接入流程。启动时遇到传输不可用后按 1、2、4 秒递增重试，上限 30 秒，HTTP 拒绝及本地绑定错误保持原处理。接入成功后通知桌面，通过已有 History 刷新队列核对当前选择；读回成功才移除本次加载的离线提示。

桌面启动、退出、界面及选择回归合计 84 项，82 项通过。另两项分别是本机保存失败后撤回临时气泡，以及流式预算触发中断的时序。使用相同夹具加载基线 chatManager.js 均复现原断言失败。夹具补齐了真实模块依赖与本机执行归属，原断言保留。

宿主原生与协作回归共 376 项通过、6 项跳过。
