# 手机上查看桌面群聊接力

共享话题的执行分页现在另带桌面顺序接力的只读摘要，来源是已有的共享准入、冻结计划、成员回复回执和原生请求状态。手机在「任务状态」显示进度，聊天页底部在需要接管、继续或核对时直接提示。手机原有发送、点名、流式预览与提交恢复沿用原入口。

对照使用真实 ToolBox、合成存量库副本和移动视口的隔离 Chromium。各场景通过配对授权的只读会话冷开同一话题。原版五个场景都显示「暂无任务记录」。新版结果如下。

| 场景 | 页面能回答的问题 |
| --- | --- |
| [尚待接管](unassigned/work.png) | A 的正式回复已确认，下一位是 B，应回另一台有权桌面接管。 |
| [已接管](waiting/work.png) | 当前负责的桌面是 deviceB，应在该桌面继续。 |
| [派发后中断](unknown/work.png) | B 已派发、结果待核对，A 的正式回复保留。 |
| [人工结束](ended/work.png) | 同一 Work 剩余接力已停止，B 仍为结果待核对，History 中没有 B 的正式回复。 |
| [全员完成](completed/work.png) | 原三端联验的同一 Work 已完成，A、B、C 三条回复均有正式回执。 |

[改前截图](unknown/before.png) · [五组逐项对照、Work 与消息 ID](summary.json)。每组目录包含接口返回、冷开前后浏览器核对和存量账本校验。观测阶段模型、工具调用均为零。

另取等待接管的库副本，由被授权的桌面身份实际调用接管和继续接口。已打开的只读 PWA 在同一页面依次显示「等待桌面继续」和「等待 B 的正式回复」。没有为 B 派发请求。两次状态变化只产生桌面端原有控制回执。[实时转换回执](live-transition.json)

查询沿用话题读取授权。原移动执行分页、总数和精确提交查询保持独立；首屏的近期和待处理两类桌面摘要分别最多 16 笔。长名单展示前 128 个位置及范围外当前或未知的位置，总人数和已确认数来自全计划。服务端测试覆盖冻结名称、v1/v2、只读及跨空间授权、人工结清、重启、较长计划。原生与协作回归分别通过 318 和 60 项，原生套件跳过 6 项。

本次验收环境为隔离浏览器。原手机的现有配对及正在使用的测试服务保留，尚未在实体 Firefox 上打开新版接力卡片。
